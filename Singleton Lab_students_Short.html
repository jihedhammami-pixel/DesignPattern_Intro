Recap: what you need to know

Read, play with the simulators, and come back here to revise. Every exercise uses these ideas.

1. The idea

"Ensure a class only has one instance, and provide a global point of access to it."Gamma, Helm, Johnson & Vlissides · Design Patterns (1994) · one of the five GoF creational patterns

Think of a football match: there is one scoreboard, and every player, referee and fan reads the same board. If everyone had their own scoreboard, they would soon disagree about the score.

3. Eager or lazy? When is the object created?

Eager

The field is static final and set immediately. The object is created when the JVM initializes the class, on its first use.

Lazy

The field starts as null. The object is created on the first call to getInstance(), if it doesn't exist yet.

Remember

Eager = created when the class starts. Lazy = created when someone first asks.

4. The danger: two threads at the same time

The lazy test if (instance == null) instance = new X(); is two steps: check, then act. Another thread can run its own check in between, like two drivers who both see the same empty parking spot. In the simulator, you are the scheduler.

Remember

"Check, then act" is not atomic. Fix it with a lock, double-checked locking with volatile, the holder idiom, or an enum.

6. Java 25 tools you will use

☕ Single-file programs

java File.java compiles and runs one file. Java 25 also allows compact source files with void main() (JEP 512). This lab keeps the classic public static void main(String[] args), which still works.

🧵 Virtual threads

Very cheap threads: start thousands with Executors.newVirtualThreadPerTaskExecutor() inside a try-with-resources block. Closing it waits for all tasks. The exercises give you this code ready-made.

🔒 synchronized is fine again

Since Java 24 (JEP 491), a virtual thread inside synchronized no longer blocks its carrier thread.

7. Good use, bad use

✔ Good candidates

Something that exists once (the runtime, a device, a registry); stateless or immutable helpers; a shared thread-safe resource such as an ID generator.

✘ Warning signs

Used only to avoid passing a parameter; holds mutable global state, so tests depend on each other; hides dependencies.

8. Pitfalls

MistakeWhy it is a problem
Public constructorAnyone can call new, so there can be many objects.
Lazy without synchronizationTwo threads can both see null (simulator 3).

Serializable without readResolve()Deserializing creates a second object.
ReflectionsetAccessible(true) can call a private constructor. Enums are protected.

1Definition

  • Creational GoF pattern.
  • One instance per class.
  • One global access point.

2Ingredients

Private constructorPrivate static fieldPublic static getInstance()

3Eager vs lazy

  • Eager: static final, created when the class initializes. Thread-safe for free.
  • Lazy: starts null, created on first getInstance(). Needs care with threads.

4Threads

  • Race: two threads see null and both create.
  • DCL: check, lock, check again, create.
  • volatile: no thread sees a half-built object.
