1. L'idée

« Garantir qu'une classe n'a qu'une seule instance, et fournir un point d'accès global à celle-ci. »Gamma, Helm, Johnson & Vlissides · Design Patterns (1994) · l'un des cinq patrons de création du GoF

Pensez à un match de football : il y a un seul tableau d'affichage, et tous les joueurs, l'arbitre et les supporters lisent le même tableau. Si chacun avait son propre tableau, ils ne seraient vite plus d'accord sur le score.

3. Eager ou lazy ? Quand l'objet est-il créé ?

Eager (immédiate)

Le champ est static final et initialisé tout de suite. L'objet est créé quand la JVM initialise la classe, à sa première utilisation.

Lazy (paresseuse)

Le champ commence à null. L'objet est créé au premier appel de getInstance(), s'il n'existe pas encore.

À retenir

Eager = créé quand la classe démarre. Lazy = créé quand quelqu'un le demande pour la première fois.

4. Le danger : deux threads en même temps

Le test lazy if (instance == null) instance = new X(); se fait en deux étapes : vérifier, puis agir. Un autre thread peut faire sa propre vérification entre les deux, comme deux conducteurs qui voient la même place de parking libre. Dans le simulateur, c'est vous l'ordonnanceur.

À retenir

« Vérifier, puis agir » n'est pas atomique. On corrige avec un verrou, le double contrôle avec volatile, l'idiome du holder ou une enum.

☕ Programmes en un seul fichier

java Fichier.java compile et exécute un fichier. Java 25 permet aussi les fichiers source compacts avec void main() (JEP 512). Ce labo garde le classique public static void main(String[] args), qui fonctionne toujours.

🧵 Threads virtuels

Des threads très légers : on en lance des milliers avec Executors.newVirtualThreadPerTaskExecutor() dans un bloc try-with-resources. Sa fermeture attend toutes les tâches. Les exercices vous donnent ce code tout prêt.

🔒 synchronized redevient acceptable

Depuis Java 24 (JEP 491), un thread virtuel dans un bloc synchronized ne bloque plus son thread porteur.

7. Bon usage, mauvais usage

✔ Bons candidats

Ce qui n'existe qu'une fois (le runtime, un périphérique, un registre) ; des utilitaires sans état ou immuables ; une ressource partagée et thread-safe, comme un générateur d'identifiants.

✘ Signaux d'alerte

Utilisé seulement pour éviter de passer un paramètre ; contient un état global modifiable, donc les tests dépendent les uns des autres ; cache les dépendances.

1Définition

  • Patron de création du GoF.
  • Une seule instance par classe.
  • Un seul point d'accès global.

2Ingrédients

constructeur Privéchamp Privé statiquegetInstance() Public statique

3Eager ou lazy

  • Eager : static final, créé à l'initialisation de la classe. Thread-safe sans effort.
  • Lazy : commence à null, créé au premier getInstance(). Attention aux threads.

4Threads

  • Compétition : deux threads voient null et créent tous les deux.
  • Double contrôle : vérifier, verrouiller, vérifier encore, créer.
  • volatile : aucun thread ne voit un objet à moitié construit.
